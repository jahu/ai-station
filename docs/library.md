# Library management

Library manages general Artifacts, not an image-only store. Import uses the existing bounded image/WAV upload adapters; generated outputs retain their Run and parent relationships. Search, type filters and pagination operate on persisted artifact records. The collection grid is one keyboard sequence (arrows, Home, End, Enter inspects) with unique Inspect names; decorative type icons stay out of the tab order. Run inspector artifact cards reuse that sequence. The input picker uses the same sequence with unique Choose names; Enter selects or deselects the focused file. Images Edit/Recompose/Upscale attach through that dialog. Audio and Avatars keep an inline picker with the same sequence; Enter attaches the focused file.

The inspector loads `GET /api/artifacts/{id}/lineage` and shows resolved source and derived artifacts across image, audio and video records. Sources keep stored parent order; derived rows are newest first, at most 50. Missing IDs are omitted; self-references and duplicate parents are ignored. Artifacts in Trash stay in the graph. Each strip is a keyboard sequence with unique Source or Derived names; Enter inspects the related artifact. The endpoint does not create a Run.

User-editable display titles and notes are separate from immutable generation parameters, original filenames, hashes and paths. Versioned updates reject stale edits. Moving an artifact to Trash hides it from the normal Library and new input pickers; it does not delete bytes or break historical Runs, existing inputs or source lineage. Trash supports inspection and restoration. Permanent file deletion is intentionally separate from this reversible action.

Run-scoped artifact listing includes trashed artifacts for audit continuity. Direct inspection and media delivery remain available locally. Mutations on Run-owned artifacts append structured events; metadata operations do not create execution Runs. Migration 0005 adds the library fields without moving media files.
