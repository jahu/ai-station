# Inspectable rolling conversation summaries

Users can explicitly update a conversation summary or enable automatic maintenance in Conversation memory. The automatic-memory toggle is a keyboard sequence with a unique Summary name; Space or Enter selects it and does not invent a summary Run. Both use a normal local-model Task/Run. Each update combines the previous enabled summary with a bounded next segment of older eligible messages, leaving the newest eight messages verbatim. Failed, canceled or interrupted updates never replace the current summary. Full message history remains intact.

The persisted summary record links its source Run, exact source message IDs, coverage boundary, character offset for a partial last message, previous summary and editable conversation-scoped Memory entry. The UI exposes the result and provenance. Disabling or deleting that Memory entry stops its use immediately for future queued requests; older summaries are not silently restored. Already queued Runs keep their immutable context snapshots. Updating a summary while its prior Memory entry changes fails for inspection rather than overwriting that edit.

Chat combines an enabled summary, its recent bounded message window and enabled pinned context. Summary text is marked as potentially imperfect reference material. Scope filtering prevents another conversation's summary from entering the request. Summarization is local, cancellable and visible in conversation activity and Run history. Automatic calls require a saved user opt-in. One conversation still allows only one active Run. Each update processes at most 200 older messages and 48,000 source characters. An individual older message that exceeds the remaining budget is split into labeled character-range chunks; coverage records the exact offset so the next update continues the remainder instead of skipping or repeating it. Chat requests include the uncovered remainder of a partially covered message in the ordinary recent-message window. Generated summaries are limited to 8,000 characters. Automatic maintenance queues at most one update after a successful Chat answer when uncovered eligible context reaches 16 messages or 40,000 characters. The newest eight messages still remain verbatim. The summary Run links to the answer that triggered it; a failed or canceled answer creates no update. The next message waits while the summary is active and then snapshots its completed result. A failed summary preserves the answer and earlier summary, and is never blindly retried. Disabled/deleted summary memory suppresses automatic recreation; manual updates remain available. Existing and new conversations default to automatic maintenance off.
