# AI Station 0.1.0

Your own AI. Made simple. This release brings guided Linux/Windows installation,
private accounts and persistent creative workspaces to the local AI workstation.
Your existing conversations, models, agents, memory and artifacts stay yours.

## What's new

- **Install, choose a model, start creating.** Desktop packages include Python
  and the compiled application. Guided setup checks hardware and storage, shows
  model sizes/licenses, and verifies downloads. Local conversation, memory,
  images, music, video, avatars, expressive voice and film-sound profiles use
  the same inspectable Runs. A profile is offered only with its actual readiness.
- **Private accounts.** First startup creates an administrator. Users have
  separate conversations, creative histories, Library, memory, agents, files and
  settings; models and hardware are shared. Optional TOTP, recovery codes,
  independent device sessions and Keep me logged in are included. Administrative
  inspection is explicit.
- **Return to your creative work.** Images, Video, Music, Speech and Avatars keep
  saved inputs, progress, results and feedback-driven variants across navigation,
  refresh and restart. Measured stages/estimates cover complete tasks; unknown
  progress is not a fabricated percentage.
- **Better prompts and search.** Optional local prompt improvement preserves
  original/effective text and exact scripts/lyrics. Auto can choose Qwen for
  structural edits while respecting an explicit image-model choice. Web searches
  use the selected model to prepare contextual queries; explicit pages can be read.
- **Voice, sound and editing.** Optional Fish S2 Pro adds expressive delivery and
  pitch-preserving pace. MMAudio creates separate scene effects/ambience. Saved
  timeline revisions combine video, speech, music and effects with trim, position,
  gain, fades, mute, preview and export.
- **Preserving operations.** Packaged Start/Stop, normal OS restart recovery and
  stable updates retain data. Linux graphics setup uses a separate OS-authenticated
  fixed helper. Completed deletion cards can be dismissed persistently without
  deleting Run history.

## Install

Download the official assets from [GitHub Releases](https://github.com/jahu/ai-station/releases):

| Platform | Asset | Qualified first-use scope |
| --- | --- | --- |
| Ubuntu 24.04 x86-64 | `AI-Station-0.1.0-linux-amd64.deb` | Clean CPU installation and first reply; separate existing NVIDIA workstation/media profiles. |
| Windows 11 x64 | `AI-Station-0.1.0-windows-x64-Setup.exe` | Actual private WSL2 installation, CPU model and first reply. Physical NVIDIA inference is unverified. |

1. Install the package for your OS. On Ubuntu use your package installer; an
   advanced fallback is `sudo apt install ./AI-Station-0.1.0-linux-amd64.deb`.
   Required OS permissions are requested through the system, never through Chat.
2. Open **AI Station** from your applications menu/desktop controls. Windows
   prepares a private WSL2 environment and may ask for an ordinary OS restart.
   Existing WSL distributions, external runtimes and drivers are not taken over.
3. Create your administrator account. Select a recommended model, review its
   download/license/storage requirements and start with a short conversation.
4. Enable other capabilities when you need them. Large media models require
   additional disk space and profile-specific RAM/VRAM; a CPU reply does not
   establish that a video model will fit.

The exercised CPU starter needs approximately 4 GiB of model runtime RAM in
addition to the OS/application. Clean Linux testing used 8 GiB RAM; the exercised
Windows/WSL CPU profile used 16 GiB. These observations are not universal minimums
for every model. Other GPU vendors/distributions remain unqualified.

**Unsigned Windows installer — approved for this early release.** Windows may
show an unknown publisher or SmartScreen warning. Smart App Control or managed
device policies may block an unsigned application. Verify the official repository
and `SHA256SUMS`; checksums identify the file but do not replace a code signature.
Do not disable OS protection. Signing is future work; even a newly signed app can
initially show a reputation warning. See [Microsoft's explanation](https://learn.microsoft.com/en-us/windows/apps/package-and-deploy/smartscreen-reputation).

## Existing installations

Back up application data first. Finish or stop active work before applying a
desktop update. On Windows install the new package, reopen desktop controls and
choose **Update AI Station** when prompted. Normal Stop affects only the owned
station. Removing the application retains data unless you explicitly choose its
separate destructive removal operation. Do not unregister WSL or prune Docker to
perform an ordinary update.

Manual Linux deployments should follow [operations](../operations.md) and update
the control plane and Host Runner together. Existing operator-profile data needs
the documented [accounts migration](../accounts.md); do not create a new empty
database over an existing station. Models/component licenses remain separate.

## Qualification and known issues

- **Windows NVIDIA:** physical GPU first reply, scoped Stop and reboot recovery
  are scheduled by the owner after release. The CPU/WSL tests do not qualify GPU
  inference. Use QA case SETUP-164 and record the actual card/driver/profile.
- **Linux GPU:** the local two-RTX-3060 workstation has real model/media evidence.
  Fresh toolkit preparation/reboot and existing-GPU readiness are separately
  verified; their combined journey on a fresh physical GPU host is untested.
- **Voice/film quality:** real short/long/cancellation, complete-file and timeline
  checks passed. The owner will evaluate expression, fidelity and scene/sound
  correspondence after release. Success status does not guarantee perceptual
  quality; previous avatar drift and model-dependent editing limitations remain.
- **macOS:** unsupported in 0.1 because full installed startup remains unreliable.
  Native component checks are not a working consumer installer.
- **SMTP:** actual mail-account/inbox testing is deferred; push is future work.
  Shared infrastructure does not imply a supported multi-node deployment.

Python regression: **8,020 passed, 19 explicit skips**, four existing warnings.
Late helper/probe/consent/bundle changes passed 77 affected cases; stable
version/update/package families passed 159. Existing frontend/static/build and
compiled application qualification is retained where code is identical. The
offline QA exporter/importer has 29 passing tests. No unexecuted real integration
or user answer is described as a pass.

The Polish QA package contains **261 untested cases**, XLSX/CSV forms, a guide,
five synthetic input fixtures, archived catalog and release manifest. Return
your results with concrete steps, device/model and Run/artifact IDs. Do not
include passwords, private keys or unrelated private media. [QA instructions](../qa/README.md).
