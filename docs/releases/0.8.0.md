# AI Station 0.8.0 — A different face. A different voice. Still you.

## Highlights

- **Live Face swap:** use a reference face while keeping your camera scene.
- **Live Animated portrait:** the reference supplies the rendered head, hair and
  skin appearance; your camera drives expressions and relative head motion.
  Begin facing the camera with a relaxed expression to calibrate movement.
- **Optional live voice conversion:** use a short voice reference for the whole
  session. Voice runs independently alongside either visual mode; Face swap mode
  also supports voice-only sessions.
- Administrator-guided preparation checks pinned model/SDK inputs and licenses.
  The portrait extension reuses the base Live runtime instead of duplicating it.
- Explicit Start/Stop, private account access, resource reservations and owned
  process recovery use the existing Task → Run → Events → Artifacts lifecycle.
  Live camera and microphone samples are not recorded by default.

## Requirements and measured performance

The first experimental profile supports Linux x86-64, Python 3.12 and NVIDIA
compute capability 7.5 or newer, with at least 4 GiB VRAM per enabled medium and
16 GiB host RAM. Voice and visual conversion together require two compatible
GPUs. An administrator reviews the optional download and component licenses in
**Live**. The optional portrait extension adds approximately 498 MiB to a prepared
base runtime. Existing models, external runtimes and drivers remain untouched.

Browser camera/microphone capture requires localhost or a private HTTPS address.
Ordinary HTTP over a LAN cannot provide these browser permissions. Reference
motion is bounded; missing faces and large head turns may pause tracking.
This is a browser preview, without OBS/Zoom virtual-device export.

Real Linux tests on two RTX 3060 12 GB GPUs measured:

| Workload | Measured result |
| --- | --- |
| Face swap + voice, complete browser session | 10.2 fps; 65 ms visual, 135 ms voice; 544 ms preview delay |
| Animated portrait + voice, private HTTPS/WSS browser | 5.0 fps; 155 ms visual, 137 ms voice; 555 ms preview delay |
| Portrait engine alone, 60 measured 512×512 frames | 6.72 fps; median 148 ms; p95 155 ms |

Browser tests used synthetic camera/microphone devices with real local models.
Portrait-only execution also passed on one GPU. Separate real driving-video
frames confirmed transfer of gaze, mouth movement and blinks. The owner reports
positive hands-on feedback; these measurements do not claim 30 fps, universal
subjective identity quality or physical Windows GPU acceptance.

## Install or update

After publication, use **Settings → Updates → Update and restart**, keeping the
same application data directory. Linux and Windows installers continue to ship;
this new Live runtime is Linux-qualified and is not advertised as Windows-ready.
Windows installers remain unsigned. macOS remains unsupported.

## Verification

The reviewed feature was verified across all 639 configured ordinary Python test
files: 10,320 initial passes and 25 skips. Five source-snapshot failures during
parallel source changes passed on frozen source when all four affected files
were rerun together (20 passes); no failed assertion was waived. Focused Live
contracts passed another 31 cases. Frontend verification passed 1,291 tests,
lint, formatting, type checks and production build. Docker build and production/
development Compose validation passed.

Real managed preparation, both visual modes, one-GPU portrait-only execution,
optional voice, private HTTPS/WSS, correct 512×512 canvas geometry, Stop and
released resource locks were checked separately from normal fake-executor tests.
See [Live design and qualification](../plans/live-identity.md).
