# AI Station 0.3.2 — Windows 10 compatibility

## What changes

- The desktop installer and native launcher admit Windows 10 21H2/22H2 x64
  alongside Windows 11. Windows 10 requires KB5020030 or a newer cumulative
  update (build 19044/19045, revision 2311+); older revisions get a direct
  Windows Update action before prerequisite downloads or guest creation.
- Windows support setup handles the old inbox WSL found on fresh Windows 10.
  With explicit native confirmation and UAC, a fixed helper verifies Microsoft's
  WSL MSI by byte length, SHA256 and Microsoft signature, prepares only the
  documented WSL/virtualization features, and asks for a normal restart.
  Existing modern WSL is reused and temporary setup downloads are removed.
- The signed Microsoft MSI launcher is preferred over stale system stubs that
  cannot forward current WSL commands. Neither PATH nor user aliases are used.
  Existing distributions, default-distro/global WSL settings, GPU drivers and
  unrelated software stay outside this application's setup operations.
- Existing conversations, agents, media workflows and local Linux execution
  retain the 0.3.1 application behavior. There is no new database migration.

## Install or update

- `AI-Station-0.3.2-windows-x64-Setup.exe` — Windows 10/11 x64, unsigned.
- `AI-Station-0.3.2-linux-amd64.deb` — Ubuntu 24.04 x86-64.
- `AI-Station-0.3.2-QA.zip` — operator test workbook and neutral fixtures.
- `SHA256SUMS` — download checksums.

Finish active work, back up application data, and use the normal installer path.
Keep the application data directory. Windows first prepares its own WSL2 guest
and Docker Engine; Docker Desktop and your own Ubuntu distribution are not needed.
The native app remains an ordinary-user process. Only its explicit Windows
support action requests OS permission. It never restarts Windows automatically.

Windows installers remain unsigned by the owner's existing decision. SmartScreen
or local policy may warn about or block them. Use official assets, compare
checksums, and keep Windows security protections enabled. macOS remains unsupported.
Physical Windows NVIDIA inference remains a separate hardware test; no GPU was
passed through to the Windows compatibility VM.

## Validation

The detailed [compatibility report](../plans/windows-10-compatibility.md)
records the two original Windows 11-only guards and the independently observed
legacy-WSL/OS-update prerequisites. A fresh, separate Windows 10 22H2 evaluation
VM passed actual PowerShell 5.1 contracts, native Inno build, installer execution
and desktop launch. The real OS-consented WSL download/install enabled both
features, installed WSL 3.0.3, created no distributions and cleaned its temporary
MSI. The old system stub and signed current launcher were diagnosed separately.
