# AI Station 0.0.2

QA fixes and more consistent speaking avatars, following the first workstation
release. This update retains existing conversations, agents, artifacts, models
and project histories. It introduces no database migration beyond schema 0036.

## Speaking avatars with more detail

The optional Sonic engine animates a complete recording in one source-bound Run.
The real application workflow produced **40.08 seconds at native 512×768/25 fps**
on two RTX 3060 12-GB GPUs, with all 1002 frames and the complete source speech
verified. Library visibility, download hashes and complete browser playback pass.
The owner confirms a substantial improvement over the earlier result.

New configured requests use the Stable detail profile. Existing Echo histories,
plans and reviewed agents preserve their original settings. The same execution
path supports the assistant and agents, owned process cancellation, explicit
Resume, GPU admission and frozen inputs. The real agent smoke covers two seconds;
the complete 40.08-second proof is the manual application workflow.

Progress now estimates remaining animation time from actual saved events and
separates finishing from completion. The measured full workflow took **2 h 27 min
18 s**, including preparation, generation, interpolation, checks and polling.
This is not native HD or a guarantee of perfect identity/lip synchronization.
See [avatar scope](../qa/whole-avatar-follow-up.md) and
[benchmark methodology](../benchmarks.md).

## Fixes from operator QA

- Natural image questions inspect the verified image; follow-up edits and
  composition retain the intended sources, source resolution and busy LLM.
- Auto model routing uses observed context allocations. Model loading waits for
  GPU memory to be released, and runtime views prioritize the actual active model.
- Local file/data tasks follow the execution workflow, show real failures and
  resource waits, and bind standard data modules before generated statements.
- Website agents must return fresh, verified output. Bounded correction handles
  malformed proposals and ambiguous snippet edits, with offline build guidance.
- Agent results and saved revisions are usable from conversations. Generated
  drafts respect actual adapter contracts and schedule constraints.
- Retrying stopped media creates a separate Task. Avatar creation and Resume
  require an available runtime. Video offers the qualified ten-second option.
- System shares the actual GPU, CPU and RAM overview. Private-page denials have
  actionable feedback rather than an unexplained search fallback.
- A conservative operator recovery utility repairs known API port failures after
  delayed network startup, preserving the existing image and running workloads.
- The repository includes a separate responsive static product website. It uses
  the previously approved demonstration assets; it adds no public hosting or
  production Library export.

## Verification and upgrade

Qualified normal coverage contains **4755 Python/Host Runner cases**, including
nine ordinary opt-in skips: the complete 4701-case base plus all changed ETA and
startup-recovery families passed, with other source/test bytes unchanged.
The full **887-test frontend suite**, formatting, lint, types, production build,
both Compose configurations, Docker image and fake-worker/API/migration smoke
passed. An actual disposable Docker bind failure/recovery also passed. These are
the documented equivalent local gates, not a claim that all cases were rerun in
one final invocation. Hosted Actions checks remain manual by owner policy.

The reviewed runtime is already deployed on the development workstation. Its
SQLite backup and integrity checks, post-update Library playback/downloads,
LAN authentication, owned private-access state and original 131072-context local
model profile were preserved or verified. No driver/CUDA changes were made.

Other installations should follow [the upgrade procedure](../operations.md),
back up application data and rebuild their configured control plane and native
Runner together. Sonic requires separately installed, explicitly configured
offline weights/runtime and an owned user memory scope; it is disabled by
default in portable configuration. Model/component licenses remain separate
from AI Station's noncommercial license. No weights, credentials or private
operator media are included.

The issued v15 QA workbook remains historical evidence. The new profile and
positive owner feedback supplement the original Echo failure; they do not
silently alter its frozen test definition. SMTP remains deferred; push notices,
remote execution nodes and one-click model setup remain roadmap work.

This release must be promoted through an owner-approved PR to `master` and tagged
there. Internal Python/npm package versions remain `0.1.0`; the product release
tag is `v0.0.2`. See the [release policy](../release-policy.md).
