# Code in a named project from Work

In the main conversation, choose **Work**, leave the action on **Auto** and send:

- `W projekcie Pogoda: dodaj wykres temperatury`
- `In project "Weather Station": implement a temperature chart`
- `Fix tests in project Weather Station`

The current instruction must contain a change request and an explicit registered
project name. Questions and explanations remain discussion. A project heading
needs the change instruction on the same line. Names are matched case-insensitively
and completely, with quotes for clarity. Ambiguous duplicate names or multiple
projects require explicit selection in Coding tools; a shorter name cannot match
the beginning of a different name.

This creates a fresh isolated coding task through the existing worktree, proposal
and configured validation flow. Local Coding **Auto** selects an installed fitting
model with at least 100k context, independently of the small model selected for
ordinary Chat. Send snapshots the project ID and policy revision; dispatch checks
that revision again before publishing preparation. No model inference is needed
to interpret the project reference. The answer names the selected project and
retains ordinary coding progress, review, Stop and continuation in Work.

Explicit actions, an already selected coding task/project, attached media/files,
web research and new-project requests retain their existing paths. A request for
Cursor/Codex/Claude needs the usual explicit external-provider selection and
sharing consent. This inference never grants external AI, commit, push or merge.
Chat mode never derives a coding scope. History and tool output cannot supply the
project name; only the current operator instruction can.

The derived scope and source reference are persisted with the Run/user message.
Turn receipt hashing still uses the original request, so replay after a project
rename or server restart returns the same task without another worktree.
