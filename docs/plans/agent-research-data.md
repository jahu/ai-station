# Reviewed public research with offline Python/data agents

Status: planned next implementation, 2026-10-24. Research/code composition (#388)
and one bounded agent validation correction (#389) are delivered; this document
does not advertise a working research/data combination.

## User outcome

One persistent agent can read a reviewed public query/URLs, optionally combine
those observations with uploaded CSV/XLSX files, calculate with local Python and
return a checked answer, table, CSV and optional PNG/Excel/text. A public-source
analysis does not require an uploaded spreadsheet, repository registration or
financial API account. Code itself stays offline. Reuse the existing agent tools,
private workspace, Python execution and result projection.

   http_fetch. Retain exactly one execution family; external coding, media and
   deterministic market policies remain separate. Search-page reading still
   requires its own reviewed query and same-workflow search. Explicit page reads
   still require their saved public URLs. Disabled drafts may await review.
2. Existing private-project setup runs when needed. On the same agent Task,
   publish dependency-linked public observations and reuse the verified research
   handoff before the existing data worktree/generation/Python/result chain.
   One saved definition and absolute deadline cover the entire execution.
   Do not repeat research when Python repairs a script.
3. Reuse exact parent/manifest/child/dependency/definition checks from the current
   research/code handoff. Verify successful source artifacts, actual hashes,
   sizes, tools, queries/URLs and partial-source provenance. Quote content as
   untrusted data; it cannot select paths, permissions, extra sources or commands.
4. Create one bounded immutable JSON input containing the verified observations,
   derived from their source artifacts. Preserve complete bounded observations
   and truncation/partial flags, rather than silently inventing complete data.
   Supply its frozen Artifact ID through the existing read-only Python input map.
   No model-supplied UUID, arbitrary path or network reaches the container.
5. Original CSV/XLSX inputs retain their inspection/hash contracts. Allow zero
   file inputs only with a valid selected/reviewed research stage. Without
   research, retain the current minimum of one file. The Python transport already
   accepts JSON/text; do not rebuild it. Its total eight-input limit remains:
   research uses one slot, leaving at most seven uploaded files in that workflow.
6. Bind the JSON snapshot and original files to generation, every repair and final
   results. Recheck source/snapshot bytes before use; preserve transitive artifact
   lineage on source code, CSV, optional exports and report. Existing required/
   optional output allowlists, inert file validation, CPU/network/filesystem
   isolation, process cleanup, Stop and conservative recovery are unchanged.

## UI and drafting

Keep the existing tool choices, public query and URL editors, file selector and
results-first workspace. Selecting Python/data retains compatible research tools
in either selection order. Explain that files are optional with reviewed public
sources, required otherwise; reject over-limit or missing scope before launch.
Show the existing compact task-bound sources, partial-read warnings, snapshot
links, progress, result table/downloads/inline chart and Task Stop. No new IDE,
command editor or duplicate research workspace.

Enable AI-assisted disabled drafts to propose the combination only after the
execution contract exists. Never invent files, URLs, accounts or permissions.
Preserve current standalone CSV/XLSX agent behavior, conversation data references,
receipt identity and ordinary Chat Web preferences. This increment must not turn
Chat's default Web availability into an implicit public request on a data task.
