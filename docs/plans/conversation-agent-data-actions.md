# Reanalyse the files used or created by a conversation agent

A follow-up can quote an agent's report but cannot currently ask Python to
reanalyse its actual files. Resolve explicit data-file operations through the
verified conversation controller, exact final data result and original completed
Python/input scope. Start a new ordinary conversation data Task and workspace;
do not rerun the agent, inherit its schedule/tools or write into its workspace.

For analysis reuse the exact frozen original inputs plus verified captured
research/document/memory data. For instruction-only creation reuse its verified
inspected workbook/CSV, not the displayed table preview. Current bytes, inspection,
source lineage, result JSON and Python completion must still match. Historical
completed sources can outlive their execution budget; the explicit new request
gets its own bounded budget. No fresh network, memory or document scope is granted.

Work sends project automation defaults even for general instructions. Those are
configuration, not an explicit coding selection: they must not block data
reference resolution. Clear them when binding a data continuation; preserve actual
selected coding/project/tool precedence. Extend direct file-operation wording for
column updates while keeping quoted, negated and unrelated requests inert.

Freeze source IDs/snapshots/context on Send and recheck before dispatch. Missing,
failed, ambiguous, changed or cross-conversation sources cannot fall back to older
files. Group references handle multiple inputs. Show the agent-file/capture source
and actual result Run. Verify ordinary and agent data flows in Chat/Work, default
Work payloads, creation/research/document inputs, mutations at Send/dispatch,
expiration, no agent rerun and original-byte preservation. Use normal isolated
fake-model/transport tests and compiled desktop/mobile acceptance; qualify final
source before reviewed merge/deployment. No schema or native API change.
