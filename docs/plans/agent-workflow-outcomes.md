# Show the actual agent execution outcome

A successful agent_workflow Run publishes a graph; it is not proof that generation
finished. Derive a read-only execution outcome from owned same-Task Runs. Active
work retains a deterministic priority, terminal failed/interrupted/canceled stages
cannot become green solely because the publisher succeeded. Recognize only the
existing two-way bounded data/code repair links when superseding an old failure.
Require an actual final generation stage for success; keep publisher Run history
unchanged.

Expose result and email delivery separately. A completed ordinary report remains
readable while its separate email is awaiting approval, failed or canceled. Stop
still covers the whole active Task and does not grant delivery or a new run.
Do not weaken artifact byte/provenance verification or reuse older executions.
Reuse the shared projection for linked conversation status and result context;
retain exact IDs and no new schema, native transport or workload executor.

Verify publisher-success/child-failure, active ordering, no-final-result, ordinary
success, pending/failed/canceled delivery, failed delivery preparation, Stop,
valid data/code repair chains and rejected cross-Task repair references. Add
compact, explicit delivery status to desktop/mobile receipts without duplicating
agent cards. Run focused and full normal gates and qualify the exact image before
reviewed merge/deployment. Whole-platform completion remains open.
