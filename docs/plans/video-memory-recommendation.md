# Recommend an admitted video profile for new requests

PR #396 qualified an optional lower-RAM Wan profile, but requiring a manual
advanced choice still leaves ordinary new Video and Chat requests waiting for
Standard's larger reservation. Reuse that exact executor; no new GPU experiment,
model, native process option or installation is needed.

- The control plane may read existing typed native capabilities/hardware and
  recommend the available bounded profile when measured RAM is below Standard's
  reservation plus existing headroom. Unknown observations retain Standard.
  Recommendations do not reserve resources or promise immediate admission.
- Fresh landscape/text Video forms can preselect that visible recommendation;
  a manual Standard selection and every saved request take priority. Selecting
  a different format or fewer steps retains the compatible Standard path.
- Ordinary text-only video Chat/Work dispatch can use the same recommendation,
  freezing the actual selection and observed files in the new child Runs. A typed
  explicit choice overrides it; old missing fields keep their serialized identity.
  Do not auto-select it for image-conditioned requests, whose quality was not
  qualified by #396, or rewrite any existing agent definition/queued Run.
- Verify recommendations, fallback/overrides, receipts and exact worker payloads
  with synthetic hardware/fake executors. Inspect compiled desktop/mobile forms
  and run the normal gates. Reuse #396 real execution evidence only after proving
  native scope/job and final typed dispatch are unchanged; no repeated GPU run.

The worker remains authoritative for RAM/GPU locks, idle-owned-model eviction,
Stop, deadlines and recovery. Apply only after a reviewed PR to develop; preserve
the healthy native Runner when its code is unchanged.
