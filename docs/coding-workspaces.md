# Coding workspaces

The default flow is create a project by name, select an executor/model, describe the outcome and continue in a persistent coding conversation. Existing repositories and branch/validation policies remain advanced settings. Coding project radios reuse the shared list keyboard with unique Project names; Space or Enter selects the focused project and does not start a coding Run. There is no inspectable project-selection Run. Coding executor radios reuse that sequence with unique Executor names; Space or Enter selects Auto, Local AI, Cursor or Codex and does not start a coding Run. Claude Code stays unavailable. There is no inspectable executor Run. Native Cursor and Codex model radios reuse that sequence with unique Model names; Space or Enter selects Auto or an installed CLI model and does not start a coding Run. Auto remains the selected provider's CLI default. There is no inspectable model-selection Run. The assistant reuses that Coding model list for Cursor and Codex; Space or Enter selects a model and does not send. Assistant Cursor and Codex now use the same automatic file discovery as Coding start; explicit files remain an advanced option. Cursor and Codex exploration stay repository-only.

Project creation is a normal host Run. The Runner reserves a UUID-owned directory under application storage, initializes local Git with main/develop branches and a first commit, and creates a project Python environment without installing packages or fetching dependencies. Failed/canceled setup preserves its directory for inspection. The project registry is populated only after confirmed completion. No caller-selected destination or external repository is overwritten. Declared dependencies are installed later by an explicit worktree Run; see [dependency installation](coding-boundary.md).

The Coding conversation list is one keyboard sequence (arrows, Home, End, Enter opens) with unique Inspect names; decorative open icons stay out of the tab order. Inspect project and View tagged Runs stay on a saved `project_id` from `GET /api/coding/sessions` and do not start a coding Run. The open conversation shows those same links through `/runs?project_id=`. Filter project uses `GET /api/coding/sessions?project_id=` and does not start a coding Run. Project details list those conversations from the same query; Enter opens the selected conversation. View all coding conversations opens the Coding filter. That list does not start a coding Run. Coding conversations reuse Task identity and its ordered Runs. Follow-up prompts reuse the owned worktree, carry bounded prior conversation context and re-explore its current source files. A project cannot execute two coding operations concurrently. Superseded proposals cannot be committed. Review states file/insert/delete totals, labels a follow-up or repair as cumulative against the task base, lists saved validation commands from that validation Run, and shows one selected patch at a time. There is no inspectable validation-command child Run. Changed files are a listbox (arrows, Home, End) with unique File names; Enter does not open a Run. Repository exploration steps use that sequence with unique Step names and stay observations on the review. Reuses the shared list keyboard. The same panel downloads the stored `changes.diff` artifact; commits and publication remain separate explicit actions.

Automatic file discovery uses the existing bounded list/read/search protocol for Local AI, Cursor and Codex. Local AI may also GET public pages and query configured search during that loop. External providers require explicit consent to sending relevant source and guidance. That consent checkbox reuses the shared list keyboard with a unique Consent name; Space or Enter selects it and does not start a coding Run. There is no inspectable consent Run. Their native tools remain disabled: the Runner executes validated read-only operations and checked file writes. A proposal may rewrite a selected file in full or replace unique exact snippets in an existing selected file; ambiguous, missing or extra keys fail closed. File deletion is unsupported. Automatic file discovery is a keyboard-navigable Explore checkbox; Space or Enter selects it and does not start a coding Run. There is no inspectable exploration-policy Run. Local AI may choose an automatic repair budget of zero, one or two attempts as keyboard-navigable radios with unique Repair names; Space or Enter selects the focused budget and does not start a coding Run. There is no inspectable repair-budget Run. Advanced file selection remains available as keyboard-navigable Edit file checkboxes; Space or Enter removes the focused path and does not start a coding Run. There is no inspectable file-selection Run. Model choices come from installed CLI metadata (Cursor model listing and Codex's model catalog cache); Auto delegates to the selected provider's default and never silently switches to an external provider.

No schema duplication is needed: setup and coding use existing Tasks, Runs, events, review artifacts and worktree ownership. UI presents conversations while retaining technical run details on demand.

## Verification

Disposable-repository integration tests cover actual Git/venv setup, setup cancellation and refusal to overwrite existing directories, both external adapters' automatic exploration, two-turn workspace reuse, stale follow-up rejection, superseded review rejection and cumulative reviewed commits. UI tests cover name-only creation, keyboard project and native Cursor/Codex model selection without starting a Run, provider/model selection, consent invalidation on project changes, navigation and follow-up submission. Chromium layout acceptance covers new project, new coding conversation and conversation history at desktop and narrow widths.

A real Codex two-turn test passed against synthetic temporary source files: the agent selected source paths, created a file, added another file on the next instruction and preserved the first result in the same worktree. No private repository source was sent. This does not claim real Cursor exploration acceptance; that path has fake-CLI integration coverage. The real opt-in test is `test_real_codex_workspace_followup` in `backend/tests/test_projects.py`, with `AI_STATION_REAL_CODEX_TESTS=1` and an `AI_STATION_CODING_WORKSPACE_EVIDENCE` output path.

Auto currently follows the saved project executor preference and the selected provider's default model. It is a deterministic default, not an LLM-based task/model classifier. Project environments are created offline. Package installation is the explicit **Install project dependencies** Run, not an implicit step of creation or validation. The bounded editing contract still applies: at most ten ordinary UTF-8 source paths and 64 KB of context/review per turn, with the same bound on cumulative uncommitted changes. Unique snippet replacements are applied in order, each matching exactly once, at most twenty per file. Existing branches and settings are available for advanced use.
