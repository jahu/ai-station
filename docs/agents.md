# Local agent lifecycle

Persistent agents use the existing Task/Run lifecycle and configured local OpenAI-compatible provider. Draft generation is deterministic and always disabled; the definition, model, selected tools, optional versioned Skills, permissions and UTC schedule must be inspectable before activation. Unsupported tool requests stay visible and block activation rather than silently pretending to execute them.

Operational tools are bounded host telemetry, the agent's own scoped memory, explicitly configured public web search, and GET of reviewed public pages. They are saved as **workflow steps**, not an unrestricted model tool loop. Each execution publishes a parent `agent.workflow` Run and then ordinary child Runs with persisted `RunDependency` edges: sequential by default, or **gated** so the report waits in `waiting_for_approval` after context tools finish. The model cannot add tools, URLs, shell commands or extra steps; invented keys fail closed and publish no children. Optional **bounded tool calling** during the report lets the model request only those selected, operational registry tools again. HTTP fetch URLs and search queries must match the saved definition. Invented tools, shell, browser, file edits and extra arguments fail closed without executing. Each extra call records events and a JSON artifact on the report Run. Arrow keys, Home and End move through those recorded calls; there is no inspectable tool-call Run. At most four rounds and three calls per round. Existing agents keep tool calling off. No filesystem editing, arbitrary shell, model-selected URLs, browser automation or external AI is granted. Every step emits events and a JSON or Markdown artifact. Canceling the parent after dispatch stops the currently active child; dependents of a failed or canceled step fail rather than inventing a report. Definitions and the step list are snapshotted when queued.

Manual, interval, five-field UTC cron and one-shot UTC datetime triggers share the same queue. Schedules persist; only one active Run per agent is allowed. Missed recurring slots are coalesced rather than replayed in a burst. Pausing prevents future launches but does not cancel an already queued/running Run. Explicit Run cancellation remains available from execution history, Home and the Run inspector.


Optional **Require approval before each Run** parks the parent workflow Run in `waiting_for_approval` with a durable Approval record. The worker does not publish child steps or load an owned llama.cpp consumer until you grant that parent. The conversation, Agents, Home and the Run inspector all post the existing approval endpoint; granting queues the Run and does not start tools from those surfaces. Deny or cancel dismisses the approval and leaves no children. **Gated** workflows additionally park the report child after context tools succeed, reusing the same Approval endpoint. Existing agents keep `sequential` mode and run without the extra report gate.

The Agents workspace supports draft review/editing, explicit enablement, Run now, pause/resume, duplication as a disabled draft, and execution history. The agent list is one keyboard sequence (arrows, Home, End, Enter inspects) with unique Inspect names. Execution history uses that sequence; Enter inspects the selected Run. Workflow steps on the parent Run inspector use that sequence; Enter inspects the child Run. Cancel stays outside the list. Editing requires the expected definition version and no active Run. Pause/resume changes the version; the editor preserves unsaved changes and offers an explicit reload. The deterministic factory copies recognized UTC schedules (including weekday/weekly/interval/`at HH:MM UTC`/`once at` ISO times), quoted public search queries, approval, gated mode, manual retry, in-app notices, remember-reports, remember-workflow observations and bounded tool calling into that disabled draft. Tools that the draft parser recognizes but cannot execute remain visible and prevent activation. Installed Skills appear as a keyboard sequence with unique Skill names; Space or Enter selects the focused pack and Review instructions stays on that row. They are not extra tools and do not invent a Skill Run. Tools on the definition use the same sequence with unique Tool names; unavailable tools stay visible and still block activation. There is no inspectable tool-selection Run. Approval, retry and notice policies use that sequence with unique Approval, Retry and Notice names; Space or Enter selects the focused row and does not invent a policy Run. Bounded tool calling and sequential or gated workflow mode use that sequence with unique Tool calling and Workflow names; Space or Enter selects the focused row and does not invent a workflow-policy Run. Linked project radios use that sequence with unique Linked project names; Space or Enter selects the focused row and does not invent a Run. A disabled draft or an already-active Run keeps that control disabled. Arrow keys, Home and End move through those steps with unique Inspect step names.

The local endpoint comes from administrator configuration, never agent output. The local model uses the shared compatible-provider stream with a bounded output and runtime; host telemetry has an eight-second request timeout. Bounded tool calling sends OpenAI `tools` on that stream. A provider that never emits tool calls still writes the report from workflow observations. llama.cpp tool-call support varies by build; this increment does not claim a particular native binary. Normal tests use fake streams. Partial reports are preserved on failure/cancellation. The shared workflow deadline covers every child; a step that starts after the budget is already exhausted fails instead of beginning a new silent loop. **Retry** is a saved policy: the default is none. Manual retry queues a new workflow Run from the failed snapshot; it never requeues the same Run, never auto-loops, and never resumes a search, fetch or inference that already had an uncertain outcome. **Notifications** are saved in-app notices (failure, success, waiting for approval). Home can mark an unread notice as read through the existing notice endpoint; that does not retry, restore or replay the Run. Email and other connectors are not enabled. Existing agents stay silent until those boxes are checked. Missed worker leases become interrupted rather than repeating inference invisibly. A one-shot launch disables its schedule immediately. Interval/cron agents keep their saved cadence when Run now is used.

No external AI, browser, email, file editing, or arbitrary shell is enabled in this slice. Agents do not control runtime processes and cannot choose extra URLs at runtime. Draft text may mention tool calling and still stores a disabled definition. Existing generic draft adapters remain unregistered.

## Versioned Skills

Installed Skills are versioned `SKILL.md` instruction packs. Selecting one injects reviewed text into the local report prompt. It does not add tools, permissions or Host Runner operations. At most four skills may be attached. Queueing snapshots file hashes; the worker fails the Run if those files changed. Draft creation can mention an installed skill by id or name and still stores a disabled definition. See [Skills](skills.md).

## Reviewed public HTTP fetch

Select **HTTP fetch**, enter one to three public `http`/`https` URLs, save the definition and then enable the agent. The URL list is required before activation; it is never inferred from the private goal, memory or model output. Draft creation may copy public URLs that were already written in the instruction, still as a disabled definition for review. Each manual or scheduled Run snapshots those URLs and `network_read` permission, GETs the pages from the control plane, and persists status, bounded text excerpts, same-origin links, timestamps and a JSON artifact before local inference.

The worker enforces cancellation and the overall agent deadline while fetching. A missing permission, non-public address after DNS, redirect to a private target or a network failure stops the Run rather than generating a report without the requested pages. Binary responses are recorded as skipped. Script and style are stripped. JavaScript is not executed, so a client-rendered site may yield little useful HTML. Page excerpts are untrusted context, not instructions or proof of a live browser session. Run details display clickable fetched-page cards independently of the model's prose. The conversation and Agents show those same cards next to the latest report from the report Run metadata, or from the matching http_fetch sibling before that copy exists. Arrow keys, Home and End move through those cards; Enter opens the selected public URL. JavaScript is not executed. External Markdown images are not loaded.

This is GET-only on ports 80/443. Credentialed URLs, loopback, private, link-local, reserved, multicast and non-public DNS answers are rejected. POST, cookies, browser automation and fetching search-result pages that were not reviewed on the definition remain unavailable.

## Scheduled internet research

Select **web_search**, enter a **Public search query**, save the definition and then enable the agent. The query is required before activation; it is never inferred from the private goal or memory. Each manual or scheduled Run snapshots the query and `network_read` permission, uses the same bounded SearXNG tool as Chat, and persists source URLs, snippets, timestamps and a JSON artifact before local inference. Tool availability reflects actual provider configuration. Existing drafts remain disabled after migration.

The worker enforces cancellation and the overall agent deadline while searching. Search failure stops the Run rather than generating a report without the requested evidence. Search snippets are untrusted context, not instructions or page contents. Run details display the full Markdown report, partial-output labeling and independently recorded clickable source cards. The conversation and Agents show those same source cards next to the latest report from the report Run metadata, or from the matching web_search sibling before that copy exists. External Markdown images are not loaded.

Both draft creation and definition editing reuse Chat's searchable local-server/llama.cpp model picker, including saved multi-GPU presets. Scheduled executions use the existing owned-runtime scheduling path. Each execution creates a report; change-only notification policies and arbitrary browser research are not implemented.

## Remembering reports

Select **Remember reports** in the definition to grant scoped `memory_write`. Every successful manual or scheduled Run stores an observation in that agent's own memory with source Run provenance. Select **memory_search** separately to include previous enabled memories in future reports. Neither option is enabled implicitly; stored observations are not verified facts and are never promoted to global memory.

Run details link directly to the saved entry. Memory supports editing, disabling and deleting it. Reports longer than 12,000 characters retain an explicitly labeled excerpt; the full Markdown artifact remains available. Saving memory and marking the Run successful share a database transaction. Failed or canceled Runs preserve partial report artifacts but create no memory. Worker recovery never silently retries the write or inference.

## Remembering workflow observations

Select **Remember workflow observations** to store successful telemetry, public search and HTTP fetch child Runs as own-scope observations tagged `agent-workflow` with source Run provenance. `memory_search` is not copied. This is independent of **Remember reports**; existing agents stay off. Failures, cancellation and missing `memory_write` create no memory. Oversized observations keep a labeled 12,000-character excerpt; the JSON artifact remains on the step Run. Retention and successful step state share one transaction. The report cannot choose the scope. See [memory contracts](memory.md).
